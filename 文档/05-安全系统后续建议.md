# dsh-charlotte 安全系统后续建议

更新时间：2026-11-24
范围：上一轮安全审计系统实现后的后续工作。按优先级排序，不改变现有安全边界。

## 1. 外部技能目录的“挂载前审查”硬隔离

现状：外部目录由 provider 只读挂载，插件启动后技能即可见；首次打开安全中心或全量审计才会扫描，使用前闸门会再次扫描并阻止 HIGH/CRITICAL。

建议：把未审查的挂载技能放入“待审查”状态，审查通过前不进入模型可调用列表。需要 provider 层增加一个可持久化的允许列表，并与安全历史中的 finding 状态联动。

验收：新挂载目录中的技能在审查前不可被模型调用；用户审查后只放行该技能，不影响同目录其他技能。

## 2. 配置变更的即时安全审计

现状：配置没有运行时变更 API，配置改动后需要重启，并在首次打开安全中心时触发 quick scan。

建议：为配置文件增加变更监听，或在宿主加载配置的入口暴露一个 reload 事件；配置变更后只跑 config audit，并把结果关联到配置版本。

验收：新增/删除 extraDirs、修改 source 根目录后，安全中心在不重启的情况下出现对应 finding。

## 3. 关闭扫描到执行之间的 TOCTOU

现状：安装、启用、使用前会按内容哈希重扫，但宿主随后读取 SKILL.md 注入上下文，两者之间仍可能被替换。

建议：在 agent/pre-step 观察到 skill-invocation 时，重新计算技能正文哈希；与最近一次扫描的哈希不一致就记录 SEC-FS-005 并阻止该回合，或至少显示明确警告。

验收：扫描通过后替换 SKILL.md，下一次真实调用被阻止并留下审计记录。

## 4. 把 API 静态文本审计升级为路由声明

现状：lib/security/api-audit.js 通过读取 lib/api.js 源码中的守卫字符串判断边界是否还在。重命名或等价重构会造成误报。

建议：在 API 层维护一份路由清单，声明每个路由的鉴权、Host、Origin、workspace、body 上限和路径校验要求；安全审计读取清单并配合运行时探针验证。

验收：删除任一守卫时，审计仍能定位到具体路由，而不是依赖字符串是否出现。

## 5. 调用方令牌与读取接口

现状：设置 CHARLOTTE_API_TOKEN 后变更接口需要 x-charlotte-token，但 GET 读取仍只依赖 loopback + Host + CORS；捆绑 UI 不会自动发送该头。

建议：为无头/集成场景提供完整的读取令牌方案；如果桌面 UI 需要令牌模式，增加一次性握手或本地代理注入，而不是把令牌写进页面。

验收：令牌模式下未授权的 GET 被拒绝，且桌面 UI 有明确配置路径。

## 6. 真实浏览器 E2E 与可访问性回归

现状：客户端有 hermetic smoke、SSR render probe，但没有真实浏览器点击流；安全中心、详情页 tab、修复预览和报告下载没有端到端覆盖。

建议：增加 Playwright 测试，覆盖打开技能详情、默认 Introduction、切换四个 tab、键盘方向键、长文滚动、Use/Copy、接受风险、导出报告。

验收：CI 中可在无头浏览器跑完这些交互，并校验焦点和 aria-selected。

## 7. 性能基准与缓存调优

现状：没有基准数据；quick scan 依赖内容哈希缓存，full audit 强制重扫；状态接口最多返回 400 条 finding。

建议：用真实技能库测量单技能扫描、全量扫描、状态轮询和详情页首屏耗时；为超大技能设置分级上限，并记录缓存命中率。

验收：给出 p50/p95 数据；超过阈值的技能有明确的 partial 状态和用户提示。

## 8. Windows 路径语义

现状：已验证 ..\\、盘符和 UNC 的拒绝；Windows 大小写不敏感、系统目录、junction 的语义未完整验证。

建议：增加 Windows 专用测试矩阵，覆盖 C:\\Windows、%USERPROFILE%\\.ssh、大小写变体、junction/symlink。

验收：Windows 上敏感目录和大小写变体均被拒绝，且不误伤用户自有目录。

## 9. 扩大“安全修复”的覆盖范围

现状：唯一自动修复是去除不可见字符，且只在可写根内、预览并校验哈希后执行。

建议：只为可证明安全的规则增加修复，例如移除明文凭据（同时提示轮换）、修正世界可写权限、删除重复/危险附件。每次修复都必须有 diff 预览、哈希校验和回滚路径。

验收：新增修复有对应测试、预览、确认和失败回滚，不引入命令执行。

## 10. 报告字段与 DSH 版本

现状：报告的 dshVersion 依赖 DSH_VERSION 环境变量，未设置时为 unknown。

建议：从宿主上下文或 DSH 包清单读取真实版本，并把插件版本、扫描器版本、配置版本一起写入报告。

验收：任意部署下报告都能给出可核验的 DSH 版本，或明确标注 unavailable 而不是猜测。
